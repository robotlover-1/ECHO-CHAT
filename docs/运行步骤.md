# ai-chat 本地运行步骤

## 最简方式（推荐）

二进制与前端编译好之后，日常启停只需两条命令：

```bash
cd /home/pp/Desktop/ls_study/proj/9.1-kvstore
./start.sh    # 一键后台启动全部 8 个服务 + kvstore（二进制/前端缺失或过期会自动补编译）
./stop.sh     # 一键全部停止；或 ./stop.sh <服务名> 停单个
```

- 各服务日志在 `runtime/logs/<服务名>.log`，排查时 `tail -f` 对应文件
- 强制全量重编译后启动：`./start.sh --rebuild`

> 本项目已重组为单一仓库 **9.1-kvstore**，ai-chat 各组件直接位于仓库根目录。

项目根目录：`/home/pp/Desktop/ls_study/proj/9.1-kvstore`（下文用 `BASE` 代表）

## 0.5 启动 kvstore（自研 Redis，多轮上下文缓存）

```bash
# kvstore 二进制与源码在 $BASE/kvstore/，配置在 $BASE/configs/；从根目录启动
cd $BASE
./kvstore/kvstore configs/kvstore-ai.conf
```

验证：`redis-cli -h 127.0.0.1 -p 5160 -a 123456 PING` 应返回 `PONG`。

> kvstore 编译：`cd $BASE && make kvstore`（本机 clang/libbpf 齐全，编译不须 root，运行时 BPF 加载失败会自动降级 TCP）。

## 1. 一次性准备

### 1.1 前端编译（产物会复制到后端 www）

```bash
cd $BASE/ai-chat-web
pnpm install --fetch-retries=15    # 网络抖动时加重试，或直接 pnpm bootstrap
pnpm build-only                   # 产物在 dist/
cp -r dist/. ../ai-chat-backend/www/
```

### 1.2 编译 Go 服务（也可直接用 `go run`，见步骤 2 注释）

产物统一放到 `$BASE/bin`（已加入 .gitignore，重启不会丢）：

```bash
mkdir -p $BASE/bin
cd $BASE/ai-chat-backend            && go build -o $BASE/bin/ai-chat-backend    ./cmd/
cd $BASE/ai-chat-service/chat-server && go build -o $BASE/bin/ai-chat-service    .

cd $BASE/mock-openai-api            && go build -o $BASE/bin/mock-openai-api    .
cd $BASE/openai-api-proxy           && go build -o $BASE/bin/openai-api-proxy   .
```

## 2. 启动服务（按顺序，先依赖后依赖方）

每个服务开一个终端，都在**自己的项目目录**下运行（因为配置文件里的日志路径是相对路径）。

### 2.1 tokenizer（Python，端口 3002）
```bash
cd $BASE/tokenizer
nuxt --port 3002 --module tokenizer.py --workers 2
```

### 2.2 敏感词过滤（gRPC，端口 50053）
```bash
cd $BASE/keywords-filter
$BASE/bin/keywords-filter --config=dev.config.yaml --dict=dict.txt
```
> `dict.txt` 是敏感词字典。也可用 `go run . --config=dev.config.yaml --dict=dict.txt`

### 2.3 关键词过滤（gRPC，端口 50054）
```bash
cd $BASE/keywords-filter
$BASE/bin/keywords-filter --config=dev.kw.config.yaml --dict=keyword-dict.txt
```

### 2.4 mock-openai-api（模拟 OpenAI，端口 8083）
```bash
cd $BASE/mock-openai-api
$BASE/bin/mock-openai-api --config=dev.config.yaml
```
> 没有真实 OpenAI key 时用这个模拟程序。真实场景可替换为 openai-api-proxy（境外代理）。

### 2.5 openai-api-proxy（代理，端口 8084）
```bash
cd $BASE/openai-api-proxy
$BASE/bin/openai-api-proxy --config=dev.config.yaml
```
> 其 `base_url` 指向 mock（`http://localhost:8083/v1`）。

### 2.6 ai-chat-service（gRPC 主服务，端口 50055）
```bash
cd $BASE/ai-chat-service
$BASE/bin/ai-chat-service --config=dev.config.yaml
```
> 配置已改为本地：MySQL `127.0.0.1:3306`、Redis `127.0.0.1:6379`、tokenizer `http://127.0.0.1:3002`。
> 注意：腾讯向量库（vectorDB）仍不可达，单轮对话不影响；多轮带上下文检索的功能会受影响。

### 2.7 ai-chat-backend（HTTP 入口，端口 7080，提供前端页面）
```bash
cd $BASE/ai-chat-backend
$BASE/bin/ai-chat-backend --config=dev.config.yaml
```

     -H "Content-Type: application/json" \
     -d '{"prompt":"你好","options":{}}'

   ```bash

     -e "SELECT id, user_msg, ai_msg, req_tokens FROM chat_records ORDER BY id DESC LIMIT 3;"
   ```

## 4. 停止服务

**推荐按端口停**（一条命令停全部 8 个服务，不依赖进程名/命令行匹配，最稳妥）：

```bash
fuser -k -TERM 3002/tcp 50053/tcp 50054/tcp 50055/tcp 7080/tcp 8083/tcp 8084/tcp 5160/tcp
```

> 说明：`fuser -k -TERM <端口>/tcp` 会给监听该端口的进程发 SIGTERM。`-TERM` 是优雅停止；不加则默认 SIGKILL。5160 是 kvstore。

也可以按进程名逐个停（Go 服务进程名就是二进制名）：

```bash
pkill -x ai-chat-backend
pkill -x ai-chat-service
pkill -x keywords-filter    # 敏感词、关键词两个实例都会被停
pkill -x mock-openai-api
pkill -x openai-api-proxy
fuser -k -TERM 3002/tcp     # tokenizer（nuxt 进程，用端口停）
fuser -k -TERM 5160/tcp     # kvstore（进程名是 kvstore）
```

> 注意：不要用 `pkill -f $BASE/bin` 或 `pkill -f "tokenizer.py"` —— `-f` 按整条命令行匹配，会误杀命令行里刚好包含该路径/字样的终端 shell。

停止后确认 8 个端口都已释放：

```bash
ss -tlnp | grep -E "3002|50053|50054|50055|7080|8083|8084|5160" || echo "全部已释放"
```

## 5. 常见问题

- **pnpm install 网络报错（ECONNRESET）**：网络抖动，加 `--fetch-retries=15` 重试；npm 镜像已设为华为源。
- **ai-chat-service 启动卡住**：确认 MySQL/Redis/tokenizer/两个过滤服务都已先启动（gRPC 客户端启动时会连它们）。
- **聊天返回失败**：确认 mock(8083)/proxy(8084) 已启动，且 `openai-api-proxy/dev.config.yaml` 的 `base_url` 指向 mock。
