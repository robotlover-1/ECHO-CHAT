## 3. gRPC 方法面（待迁移的 4 个方法）

| gRPC 服务 | 方法 | proto | 调用方向 | zrpc method 常量（计划 §7.1） |

| Chat | ChatCompletionStream（server-stream） | 同上 | backend → ai-chat-service:50055 | chat.completion_stream |

## 5. 调用链行为基线（保持不变项）

- 敏感词命中 → 返回固定拦截文本，不调用 LLM（fail-closed）。
- 关键词提取失败 → 降级为空列表，Chat 继续（fail-open）。
- 语义缓存命中 → `source=cache`，不扣额度；未命中 → `source=llm`，扣额度。
- LLM 空 content → 保留现有重试与兜底提示；`finish_reason=length` → 截断提示，不写语义缓存。
- 浏览器断开需能取消 chat-service 上游 LLM HTTP 请求（当前实现待 Task 7 验证）。

## 6. 性能基线（方法论，执行推迟说明）

Task 0 阶段不重复跑全量 benchmark。性能对比的**方法与记录口径**见
`docs/superpowers/plans/2026-09-04-echo-chat-c-zrpc-cross-language-migration-plan.md` §12.4 与 §14.2：

- 维度：同机与跨 VM；并发 1/10/50/100；filter unary、Chat 缓存命中短流、LLM 长流；
  1 KiB/16 KiB/64 KiB/1 MiB payload。
- 记录：QPS、首 chunk P50/P95/P99、完整响应 P50/P95/P99、CPU/RSS/FD/goroutine、
  cgo 调用次数与均耗、每请求网络字节、错误/超时/取消率。
- 回滚阈值：zrpc 错误率连续 5 分钟高于 gRPC 基线 1 个百分点；P95 首 chunk 劣化 >20%。

gRPC 基线数值将在"双栈灰度"阶段（Task 9 前置）用同一脚本先记录，再与 zrpc 对比。
